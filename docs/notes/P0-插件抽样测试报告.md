# P0 抽样测试报告 · dsh 插件原生化可行性

> 2026-11-16 ｜ 数据来源：GitHub `topic:dsh-plugin` ｜ 样本：140 个真插件 + 20 个方向样本

---

## 一、三句话结论

1. **可行，而且比预估的简单得多。** 插件不打包 React，而是向宿主 `require("react")`；UI 通过 `slots.register()` 挂到具名插槽。**插件代码一行都不用改**，改的是宿主。
2. **"安装时转译"这一步可以取消。** 不需要 rollup / sucrase / rebundle。宿主只要换掉 `__ModuleLoader__` 的实现，就能接管全部插件的 React 与渲染目标。
3. **真正的工作量在"重写 11 个宿主 client 包"，不在插件。** 依赖高度集中，做前 7 个包可覆盖一半以上的插件。

## 四、决定性发现：插件的 client 契约

真实产物的头部（`dsh-windows-mcp`，88 KB）：

```js
window.__ModuleLoader__.load({
  id: "dsh-windows-mcp",
  factory: function (require) {
    var module = { exports: {} };
    var exports = module.exports;
    var React = require("react");          // ← 宿主注入，不是自己打包
    var SLOT_NAME = "conversation.input.left";
    // ...
    exports.apply = apply;
    exports.inject = inject;
  }
});
```

三件事，没有第四件：

1. `require("react")` —— **模块解析权在宿主手里**
2. `React.createElement(...)` —— 造树，不碰 DOM
3. `slots.register("conversation.input.left", Component)` —— 挂到具名插槽

验证结果（5 个样本）：

| 插件 | `__ModuleLoader__` | `require("react")` | `require("react-dom")` | `slots.register` |
|---|---|---|---|---|
| dsh-windows-mcp | ✅ | 1 | 0 | 4 |
| dsh-pocket | ✅ | 3 | **0** | 4 |
| dsh-agent-teams | ✅ | 1 | **0** | 6 |
| dsh-free-search | ✅ | 1 | 1 | 4 |
| dsh-wallpaper-engine | ❌（ESM 形态） | 1 | 1 | 0 |

**多数插件根本不用 `react-dom`**——它们只造树，挂载由宿主完成。这意味着：

> 原生化的正确定义不是"把插件界面转成原生"，而是**"把宿主的挂载点换成原生"**。
> 插件还是那句 `slots.register('xxx', MyComponent)`，只是 `MyComponent` 被画成了原生控件。

### 附带验证：运行时接管可行

Node 22 上实测，用 `module.register()` 的 resolve hook 可以把 `import "react-dom"` 完整替换成自定义模块，插件源码零改动：

```
$ node --import ./register.mjs plugin-client.mjs
NATIVE_RENDERER_GOT: {"type":"Portal","children":{"type":"Message",...}}
```

对 `__ModuleLoader__` 形态的插件，连这层 hook 都不需要——直接在宿主的 `require` 实现里返回自己的 React 即可。

## 六、三个新发现的风险

| # | 发现 | 影响 | 处置 |
|---|---|---|---|
| **R8** | **6/20 的 `exports['./client']` 指向的文件不在 git 里**（`lib/client.js` / `dist/client.js` 被 gitignore） | "拉源码"这条路对 30% 插件拿不到产物 | 改为：**清单与 patch 从仓库读，client 产物从 npm 包取**；两者都缺的，提示作者补充 |
| **R9** | 一部分插件用 ESM + `import "react-dom"`，不用 `__ModuleLoader__` | 需要双通道接管 | Node 侧用 `module.register()`（已验证）；宿主侧按 `__ModuleLoader__` 判断走哪条 |
| **R10** | 6/6 样本重度使用 `document` / `querySelector` / `MutationObserver` | 必须在原生侧实现影子 DOM | 见下节工作量修订 |

## 七、对 v2 计划的修订

| 项 | v2 原估 | 修订后 | 原因 |
|---|---|---|---|
| 安装期构建（rollup + sucrase + rebundle） | 2–3 人月 | **取消** | 宿主接管 `require` 即可，不需要重打包 |
| 插件改造 | 按"可重定向率"筛 | **0** | 插件零改动 |
| P1 单插件直通 | 4 周 | **2 周** | 省掉构建链，直接接 slot |
| 组件库重写 | 4–6 人月 | **4–6 人月（不变）** | 仍是最大块 |
| 影子 DOM shim | 2 人月 | **2–3 人月（上调）** | 样本证明 DOM 依赖普遍 |
| 总计 | 8–9 人月 | **6–7 人月** | 转译层消失 |

**红线判定**：可重定向率 = **14/14 = 100%**（已判定部分），远高于 40% 红线 → **方案成立，可进 P1**。
