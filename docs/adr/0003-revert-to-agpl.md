# ADR-0003：许可证改回 AGPL-3.0 + 商业授权

**状态：** Accepted
**日期：** 2026-11-23（同日推翻 [ADR-0002](0002-license-noncommercial.md)）
**决策面：** 仓库与 APK 的授权模型。不涉及代码结构。

---

## 0. 一句话结论

用 **AGPL-3.0**。它**允许**任何人商用，但要求公开完整源码（含网络服务）；**想闭源商用才需要买商业授权**。

「禁止一切商用」这个诉求被主动放弃——因为它的代价（拿不到开源名分、被发行版和公司合规挡在门外）大于收益（挡不住真想白嫖的人）。

## 1. 为什么推翻 ADR-0002

ADR-0002 选了 CC BY-NC-SA 4.0，逻辑上确实同时满足「禁商用 + 衍生同许可」。但代价比预期重：

| 代价 | 具体影响 |
|---|---|
| 不是 OSI 开源许可 | GitHub 标 non-commercial；F-Droid、各 Linux 发行版、部分企业的开源合规白名单直接不收 |
| 源码义务弱 | CC 只说「以相同许可分享」，没有 GPL 系列「必须提供 Corresponding Source」的硬条文，落地时容易扯皮 |
| 缺专利条款 | 对软件而言是结构性缺口，只能靠商业合同补 |
| 收益有限 | 真想白嫖的人本来就不看许可证；能约束的只有守规矩的公司，而这类公司恰恰需要「开源许可」才敢用 |

而 AGPL 的三个特性正好补上：

1. **copyleft 最强档**：把「通过网络提供服务」视同分发，SaaS 也得开源；
2. **源码义务明确**：第三、四、五、六条逐条写明要提供什么；
3. **是开源许可**：能被发行版收录、能进企业白名单——先让人用起来，才有后面谈授权的机会。

## 2. 现在的授权模型

```
默认许可：AGPL-3.0-only
          ├─ 任何目的使用，免费（含商业）
          ├─ 分发 / 提供网络服务 → 必须公开完整源码
          └─ 想闭源商用 → 另购商业授权（LicenseRef-Commercial）
```

SPDX 表达式：`AGPL-3.0-only OR LicenseRef-Commercial`。

## 3. 承认的短板（不修补）

- **开源商用合法。** 竞争对手 fork 一份、自己开源、照样卖服务，AGPL 拦不住。这是选 AGPL 必然要接受的事——它挡的是「藏代码赚钱」，不是「赚钱」。
- **执行靠事后追。** 有人无视许可闭源分发，只能发函或起诉，没有技术手段。
- **AGPL 的「网络服务」判定在国内司法实践中案例少**，真打起来要看具体部署形态。

## 4. 落地清单

- `LICENSE`：AGPL-3.0 官方全文，661 行（md5 `eb1e647870add0502f8f010b19de32af`）。
- `COMMERCIAL.md`：可商用但须开源的边界、闭源商用授权申请、贡献者再许可条款。
- `NOTICE.md`：第三方组件归属；`impl/fixtures/` 明确排除在本项目许可之外。
- 关键源文件 `SPDX-License-Identifier: AGPL-3.0-only`；`impl/package.json` 用 `(AGPL-3.0-only OR LicenseRef-Commercial)`。
- 应用内「设置 → 关于 → 许可证」可查看摘要（`impl/app/lib/settings_screen.dart`，2 条 widget 测试覆盖）。
- CC 的两份文本移出仓库，存在本地 `/root/backup/licenses/`，不入库、不分发。

## 5. 不做什么

- 不在 AGPL 上附加「禁止商用」条款。AGPL 第 7 条只允许附加额外许可，不允许附加限制；硬加会让整份授权自相矛盾。
- 不再把 CC 当备选写进 README。仓库里只留一个生效许可，避免「到底哪个算数」的歧义。
